# 구현 요구사항

| 영역 | 구현 | 제한 |
|---|---|---|
| 회원 | 가입 시 계정 정보·선택 프로필·초기 취향을 한 흐름에서 입력·일괄 저장, 로그인, 서버 세션, 로그아웃, 프로필 조회·부분 수정(이름·성별·만 나이·거주지·직업·MBTI) | 이메일 인증/비밀번호 재설정은 후속 범위. 추가 프로필은 선택 입력 |
| 마이페이지 | 나의 정보 기본 표시, 세로 메뉴로 찜·최근 조회·취향·이용 및 결제 내역 개별 페이지 이동 | 기존 찜·최근 조회·결제 탭 링크도 새 경로로 연결 |
| 취향 | 회원가입 마지막 단계에서 분야·태그 입력 후 프로필과 함께 저장, 비회원 취향 체험, 마이페이지에서 관심 분야·태그 설정/수정 | 가입에서 완료한 설문은 다시 표시하지 않음. 알고리즘 학습 없이 가중치 기반 |
| 탐색 | 검색, 지역·분야·기간·무료, 정렬, 페이징, 상세 | 외부 API 키 설정 전 가상 샘플 제공 |
| 활동 | 찜, 리뷰·평점, 최근 조회, 추천 노출/클릭 | 로그인한 본인 활동만 수집 |
| 추천 | 설문+시간감쇠 조회+현재 찜, 추천 이유 | 재방문 조회 1일 중복 점수 제한, 최대 500개 후보 |
| 결제 | 로그인 사용자 모의 결제, 서버 금액 산정, 결제/이용 내역·행동 이벤트 원자적 저장 | 외부 PG/실제 청구·발권 없음. 금액이 등록된 미종료 콘텐츠 대상, 샘플 허용 |
| 환불 | 모의 결제에서는 제공하지 않음 | 취소 정책·실제 관람 확인은 후속 범위 |
| 수집 | 문화포털 목록·상세, 정규화, 중복 갱신, 주기 실행 | 키/할당량 및 이용 조건 확인 필요 |
| 배포 | Nginx 정적, FastAPI 직접 호출, MariaDB 독립 서버 | 운영 도메인/TLS·방화벽은 운영자가 구성 |

서비스 상태는 MariaDB를 사용하고 SQLite는 도입하지 않는다. 2026-11-06 요청으로 분석 이벤트를 MongoDB `oddinary.user_events`에도 적재하며 트랜잭션 outbox로 전달한다. 잔여 좌석/잔여 매수 표시와 무료 크레딧 결제는 제공하지 않는다. 샘플 정보로 실제 결제를 생성할 수 없다.
