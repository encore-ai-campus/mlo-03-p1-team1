# 행동 이벤트 계약 v1

현재 저장소는 MariaDB `behavior_events`. MongoDB는 도입하지 않는다. 이벤트로 찜·리뷰·주문 상태를 재구성하지 않는다.

공통 필드: `event_id` UUID 문자열 PK, `event_type` 문자열, `user_id` 인증 토큰으로 결정, `content_id` 해당 시 FK, `occurred_at` 서버 수신 UTC 시각, `properties` 허용된 부가 정보만 저장하는 JSON. 브라우저가 user_id나 occurred_at을 위조할 수 없다.

| 이벤트 | 생성 주체 | 용도 |
|---|---|---|
| content_view | 상세 화면, 인증 회원 | 최근 조회, 시간감쇠 추천 점수 1 |
| recommendation_click | 추천 카드 클릭 | 시간감쇠 추천 점수 2 |
| recommendation_impression | 추천 페이지의 콘텐츠 목록 | 추천 노출 분석, 점수에는 미반영 |
| search | 검색 제출 | 검색 횟수 분석. 원문 검색어 수집 안 함 |
| filter_use | 탐색 필터 변경 | 사용 분석. 분야만 optional category 저장 |
| bookmark_add / bookmark_remove | 찜 API 서버 | 실제 상태와 같은 DB 트랜잭션의 행동 기록 |

추천 노출은 추천 페이지 목록이 렌더링된 기준이며 실제 viewport 교차/시야 체류 보장은 하지 않는다. 비로그인 사용자는 원본 행동을 저장하지 않고 공개 추천을 사용한다. 동일 event_id 재전송은 첫 저장만 인정하며 payload 덮어쓰기나 사용자 변경을 하지 않는다.

찜 상태 PUT/DELETE는 멱등이지만 각 요청을 행동 시도로 기록한다. 추천 점수에는 현재 찜 상태만 사용하여 중복 요청으로 점수가 부풀지 않는다. 조회/클릭은 콘텐츠·종류·한국/UTC 날짜 중 현재 구현의 UTC 수신일 기준 일 1회만 점수에 반영한다. 30일 지수 감쇠, 회원당 최근 500개 이벤트가 계산 대상이다. 행동 수집 실패는 탐색 UI를 막지 않는다.

이벤트에는 이메일·비밀번호·카드번호·PG 비밀키·인증 응답을 넣지 않는다. 운영 보존 기간/동의/삭제 정책은 팀에서 확정해야 하며 현재 자동 보존기간 삭제 작업은 없다. 외부 DB 전달이 필요해지면 트랜잭션 outbox와 멱등 소비·재시도를 설계한다.
